## Full account

# Dispatch commit archives the task doc it cites

**What happened (2026-10-13 20:39Z → 10-14 09:17Z):** the post-merge review of PR#5669 (TASK-542) filed follow-up #5671 whose Refs cited `.agent/tasks/TASK-542-….md`. The same docs commit (b4a1068f6) moved that doc to `.agent/tasks/archive/`. On main the cited path did not exist. The dispatcher's base-presence gate held the task, exhausted its held cycles overnight and parked it under `pilot-needs-human` ("referenced path … not found on default branch"). Pilot had already started once (20:40Z) and the stale in-progress label was cleaned at 21:57Z.

**Why it is structural:** the review → archive → dispatch sequence runs in one session and one commit. The issue body is written before the `git mv`, so it cites the pre-archive path. The gate is right (SOP Rule 3b: backtick only paths on main).

**Recovery (worked, 10-14 09:17Z):** `gh issue edit` the body to the archive path, remove `pilot-needs-human`, comment the cause. The gate re-read it on the next cycle; Pilot started at 09:24Z and merged PR#5674 at 09:48Z.

**How to apply:** when a review archives a task doc and files a follow-up in the same breath, cite `.agent/tasks/archive/<doc>` in the issue, or cite the task by number in prose without backticks. Check `git ls-tree origin/main` for every backticked path before `gh issue create`.
