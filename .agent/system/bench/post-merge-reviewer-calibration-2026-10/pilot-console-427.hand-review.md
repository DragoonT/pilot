The `"usd_cents"` key check is likewise a substring of `included_usd_cents`/`remaining_usd_cents` (harmless: absence/presence still holds).
- N2 Three copies of the "switched this period" rule now exist in internal/allowance/status.go: `StatusForOrg` (`StateIsCurrent() && SwitchedToOwnAt != nil`), `KeySourceForOrg`, and the older `CurrentPeriodSwitched`. One helper would stop them drifting.
- N3 `registerUsage` builds a second `allowance.Service` with no `Meter`/`Daily`/`Packs`. Only `KeySourceForOrg` is reachable through the `KeySourceResolver` interface, so it is safe today; `StatusForOrg` on that instance would nil-panic on `deps.Meter`. Worth a comment, or a dedicated `allowance.KeySourceService` with only the two readers.
- N4 Wire change on the own-key path: `reportedUsdCents` was `*float64` without `omitempty` (serialized `null` when unknown); it now disappears. Consumers reading `row.reportedUsdCents ?? row.estimatedUsdCents` are unaffected.
- N5 `percent_used` denominators include prepaid pack tickets (`StatusForOrg` adds `packTickets` to `IncludedTickets` before `Percent`), while `included_tickets` on the wire is the plan figure minus packs. Pre-existing GH-424 semantics, inherited by the pool meter; consistent with "percent of the allowance" if packs count as allowance.

On a platform-key tenant these are now `undefined`. Follow-up on the UI repo, not a console defect.
