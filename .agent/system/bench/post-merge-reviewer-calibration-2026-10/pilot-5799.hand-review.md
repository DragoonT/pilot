### D1 — Telegram receipts digest is fail-open on `key_source=unknown`
`receipts.go:formatReceiptLine` appends `$x.xx` when `exec.KeySource != KeySourcePlatform`, and `formatReceiptsTotal` drops the total only when some row is `platform`. A box whose fetch-secrets step did not write `PILOT_ANTHROPIC_KEY_SOURCE` records `unknown` on every execution (known case: the pre-TASK-502 SSM layout, memory `founder-tenant-legacy-ssm-layout-key-source-unknown-unmetered`). Such a tenant with a Telegram connection still receives per-run `$` lines and a `$` total in the digest, while the structured brief for the same runs hides them. This contradicts the rule `structured.go` itself states ("unknown is treated like platform") and decision mem-262 (no dollars on any platform-key surface). Change both functions to `== memory.KeySourceOwn`. Self-hosted operators who want cost lines set `PILOT_ANTHROPIC_KEY_SOURCE=own`.

### D2 — Structured brief inherits the fixed 09:00→09:00 window
`storeStructured(brief.Period)` takes the period from `generator.go:GenerateDaily`, which is hard-coded to yesterday 09:00 → today 09:00 in `daily_brief.timezone`, independent of `daily_brief.schedule`. With the 8.7 D3 default of 18:00, runs completed 09:00–18:00 today are absent from today's brief and appear tomorrow; the `shipped` section is stale by up to nine hours. Pre-existing for the Slack/Telegram brief, now also the console object. Derive the period end from the run time (`now` or the scheduled slot) and the start from the previous run; this is not a scheduler-time change.
